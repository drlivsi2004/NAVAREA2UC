---
name: Cancelled task lifecycle
description: How to audit cancelled project tasks before recreating release work
---

Cancelled project tasks cannot be reopened as active work through the task
controls; only archived planning drafts have a restore path. Before creating a
replacement, compare the cancelled scope with current code, tests, reports, and
successor tasks. Recreate only the genuinely incomplete scope, and consolidate
physical evidence or release operations instead of duplicating parser work.

**Why:** Historical task cancellation can predate a later merged implementation,
and reopening every cancelled card creates duplicate or conflicting release work.

**How to apply:** Treat cancelled as a review input, not as proof of missing
code. Separate code completion, physical ECDIS evidence, and future product
scope before proposing a new task.
